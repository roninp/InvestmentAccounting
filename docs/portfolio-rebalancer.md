# Ребалансировка портфеля (PortfolioRebalancer)

## Общее описание

Одно-файловое React-приложение для управления портфелем активов Мосбиржи с автоматическим расчётом ребалансировки. Пользователь добавляет активы, загружает текущие цены через ISS API и видит, сколько нужно докупить/продать каждого актива для приведения портфеля к целевым пропорциям.

**Ключевая особенность:** расчёт выполняется **только после нажатия кнопки «Рассчитать»**, что даёт пользователю полный контроль над моментом пересчёта.

**Система учёта денежных средств:** в карточке «Деньги» отображается остаток свободных средств (`cashBalance`). Пользователь может ввести добавляемую сумму и нажать ➕ «Добавить», после чего она прибавится к остатку. При нажатии «Рассчитать» доступный бюджет (cashBalance + additionalCash) используется для докупки активов, и потраченная сумма списывается.

**Авто-распределение целей:** целевые проценты автоматически заполняются в следующих ситуациях:
- При добавлении нового актива
- При любом изменении поля актива (тикер, количество, цена, цель)
- При удалении актива

Логика: если есть активы с `targetPercent = 0`, нераспределённый остаток делится между ними поровну. Если все цели равны 0 — 100% делится поровну между всеми активами.

**Ручное распределение:** кнопка ⚖️ «Поровну» в колонке «Цель %» позволяет вручную распределить проценты между ненулевыми активами по тому же алгоритму. Актив считается нулевым, если его поле «Цель» **пустое** (пустая строка, фокус ещё не потерян), равно **null** (blur очистил поле перед нажатием кнопки) или равно **0** — во всех случаях он получит распределённую долю.

## Ключевые зависимости

- **React 18** (CDN, production-сборка)
- **Babel Standalone** — транспиляция JSX в браузере
- **Tailwind CSS** (CDN) — стилизация
- **ISS API Мосбиржи** (`https://iss.moex.com/iss/`) — получение цен активов

## Состояние компонента

Компонент `PortfolioRebalancer` управляет следующими состояниями:

| Состояние | Тип | По умолчанию | Описание |
|-----------|-----|--------------|----------|
| `assets` | `Array` | `[{SBER, 10, 245.50, 50%}, {GAZP, 20, 145.20, 50%}]` | Массив активов (2 предустановленных) |
| `loading` | `boolean` | `false` | Флаг загрузки цен |
| `error` | `string\|null` | `null` | Сообщение об ошибке |
| `nextId` | `number` | `3` | Счётчик для ID новых активов |
| `cashBalance` | `number` | `0` | Остаток свободных денежных средств (автосохраняется в localStorage) |
| `additionalCash` | `number` | `0` | Вводимая пользователем добавляемая сумма (не сохранена, пока не нажата ➕) |
| **`isCalculated`** | `boolean` | `false` | Флаг выполненного расчёта. `false` — данные изменены, требуется перерасчёт; `true` — расчёт актуален |
| **`calculatedTotalValue`** | `number` | `0` | Замороженное значение эффективной стоимости (портфель + деньги) на момент последнего расчёта |
| **`calculatedAnalysis`** | `Object[]\|null` | `null` | Сохранённый результат последнего нажатия «Рассчитать» (с учётом бюджета) |
| **`isCalculating`** | `boolean` | `false` | Флаг анимации расчёта (пульсация кнопки, спин иконки) |
| **`highlightCards`** | `boolean` | `false` | Флаг подсветки карточек сводки после расчёта |
| **`animationKey`** | `number` | `0` | Ключ для пересоздания `<tbody>` при повторном расчёте (сброс анимации строк) |

### Вычисляемые значения

- `analysis = useMemo(() => ...)` — массив с расчётными полями. **Зависит от `isCalculated` и `calculatedAnalysis`**. Возвращает `[]`, если расчёт не произведён. После нажатия «Рассчитать» использует сохранённый результат (с учётом бюджета), чтобы данные не менялись при перерендерах.
- `portfolioValidation = useMemo(() => ...)` — результат валидации суммы целевых процентов.

## Управление расчётом

### Принцип работы

1. Пользователь вводит данные (редактирует активы).
2. Все изменения **сбрасывают** `isCalculated` в `false` через `resetCalculation()`.
3. Пока `isCalculated === false`, таблица **не показывает** результаты анализа (колонки «Текущий %», «Требуется», «Купить/Продать» пусты).
4. После нажатия кнопки «Рассчитать»:
   - Фиксируется `calculatedTotalValue = PortfolioCalculator.calculateTotalValue(assets) + cashBalance + additionalCash` (эффективная стоимость)
   - Бюджет: `cashBalance + additionalCash`
   - Вызывается `PortfolioCalculator.analyzePortfolio(assets, effectiveTotalValue, budget)` — докупка ограничена бюджетом
   - Потраченная сумма списывается из `cashBalance`, `additionalCash` обнуляется
   - `isCalculated` устанавливается в `true`
   - `calculatedAnalysis` сохраняется — дальнейшие ререндеры не пересчитывают анализ
   - Запускаются анимации: появление строк, подсветка карточек

### Сброс флага

`isCalculated` сбрасывается в `false` при:
- Обновлении цен через кнопку «Обновить цены»
- (Поле ввода стоимости портфеля и дополнительной суммы убраны)

**Расчёт НЕ сбрасывается** при:
- Изменении полей актива (тикер, количество, цена, целевой процент) — результаты остаются видимыми, пользователь сам решает, когда пересчитать
- Добавлении нового актива
- Удалении актива

## Система учёта денежных средств

### Карточка «Деньги» (PortfolioSummary)

В карточке отображается текущий остаток `cashBalance`. Пользователь может:
1. Ввести сумму в поле ввода
2. Нажать ➕ «Добавить» — сумма прибавится к `cashBalance` (с округлением вниз до сотых), поле очистится

### Логика при расчёте

При нажатии «Рассчитать»:
- Доступный бюджет = `cashBalance + additionalCash` (включая ещё не добавленную сумму из поля ввода)
- `PortfolioCalculator.analyzePortfolio()` распределяет бюджет между активами, которые нужно докупить
- Сумма докупки каждого актива ограничена оставшимся бюджетом
- После расчёта: `cashBalance` уменьшается на потраченную сумму, `additionalCash` обнуляется

### Сохранение

`cashBalance` сохраняется в localStorage вместе с портфелем и импортируется/экспортируется в JSON-файлах.

## Авто-распределение целевых процентов

### Логика `distributeTargets`

Метод `PortfolioCalculator.distributeTargets(assets, emptyTargetIds = new Set())` автоматически заполняет целевые проценты. Второй параметр `emptyTargetIds` — набор id активов, у которых поле «Цель» пустое (пустая строка, фокус ещё не потерян). Актив считается нулевым, если его `targetPercent === 0` **ИЛИ** `targetPercent == null` (blur очистил поле перед нажатием кнопки ⚖️) **ИЛИ** его id находится в `emptyTargetIds`.

1. **Все цели равны 0** — 100% делится поровну между всеми активами (последнему — остаток для точной суммы 100%):
   - 2 актива → 50.0 / 50.0
   - 3 актива → 33.3 / 33.3 / 33.4
   - 4 актива → 25.0 / 25.0 / 25.0 / 25.0

2. **Есть и нулевые, и ненулевые** — оставшаяся доля `(100 - сумма_ненулевых)` делится поровну между нулевыми:
   - SBER: 50%, GAZP: 0%, TATN: 0% → SBER: 50%, GAZP: 25%, TATN: 25%

3. **Все цели ненулевые** — ничего не меняется.

> **Примечание:** параметр `emptyTargetIds` используется только при ручном распределении через кнопку ⚖️. Авто-распределение (при добавлении/изменении/удалении актива) вызывается без этого параметра.

### Механизм отслеживания пустого поля

При стирании содержимого поля «Цель» `NumericInput` вызывает колбэк `onEmptyChange(true)`, и id актива добавляется в набор `emptyTargetIds`. При нажатии кнопки ⚖️ браузер сначала отправляет `blur` полю ввода (очищая `targetPercent` до `null`), а затем `click` кнопке. Чтобы кнопка корректно видела пустое поле:

- `handleBlur` при пустом поле **не вызывает** `onEmptyChange(false)` — id остаётся в наборе пустых полей.
- `distributeTargets` считает `targetPercent == null` нулевым — даже если id выпал из набора.
- При заполнении поля извне (после распределения или ручного ввода) `useEffect` синхронизации сообщает `onEmptyChange(false)`, и id удаляется из набора.

### Триггеры вызова

`distributeTargets` вызывается автоматически при:
- **Добавлении актива** (`handleAddAsset`) — новый актив добавляется с `targetPercent: 0`, затем вызывается распределение
- **Изменении любого поля актива** (`handleUpdateAsset`) — после обновления данных вызывается распределение, что заполняет оставшиеся нулевые цели
- **Удалении актива** (`handleRemoveAsset`) — после удаления вызывается распределение для оставшихся активов

## Кнопка «Рассчитать»

### Внешний вид по состояниям

| Состояние | Цвет | Иконка | Текст | Описание |
|-----------|------|--------|-------|----------|
| `isCalculating === true` | Синий + пульсация `animate-pulse-glow` | ⏳ (спин) | "Расчёт..." | Идёт визуальный эффект расчёта |
| `isCalculated === true` | Зелёный `bg-emerald-600` + тень | ✅ | "Рассчитано" | Расчёт актуален |
| `canCalculate === true` | Синий `bg-blue-600` | 🧮 | "Рассчитать" | Данные введены, можно рассчитать |
| `canCalculate === false` | Серый `bg-slate-400` | 🧮 | "Рассчитать" | Нет данных для расчёта (disabled) |

- После нажатия «Рассчитать» строки появляются каскадно с задержкой.

## Экспортируемые компоненты

Главный компонент приложения. Содержит всё состояние и логику.

Карточки сводки портфеля. Принимает пропсы:

## Классы бизнес-логики

### `PortfolioCalculator`

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `floorMoney` | `value` | `number` | Округление денег строго вниз до сотых |
| `floorQuantity` | `value` | `number` | Округление количества строго вниз до целого |
| `calculateTotalValue` | `assets` | `number` | Сумма `quantity * price` по всем активам |
| `calculatePercentages` | `assets` | `number[]` | Процент каждого актива от общей стоимости |
| `calculateRequiredQuantity` | `asset, targetPercent, totalValue` | `number` | Сколько нужно актива для целевого процента (с округлением вниз) |
| `calculateAdjustment` | `currentQuantity, requiredQuantity` | `number` | Разница между текущим и требуемым |
| `distributeTargets` | `assets, emptyTargetIds?` | `Object[]` | Распределение целевых процентов поровну |
| `analyzePortfolio` | `assets, effectiveTotalValue, availableBudget?` | `{analysis, cashSpent}` | Полный анализ портфеля с ограничением бюджета |

### `MoexPriceService`
Сервис получения цен через ISS API Мосбиржи (акции, ETF, облигации, foreign shares, депозитарные расписки).

### `AssetValidator`
Валидация отдельного актива и портфеля в целом (сумма процентов должна быть 100% ± 0.5%).

## Примечания

- Минимальное количество активов — 2 (кнопка удаления блокируется для id <= 2)
- Максимальное количество активов — 100
- Цены загружаются автоматически при монтировании (если есть активы с тикерами)
- При `calculatedTotalValue = 0` требуемое количество для всех активов = 0
- После любых изменений данных кнопка «Рассчитать» переключается в синий цвет, сигнализируя о необходимости перерасчёта
- Подсказка «Нажмите «Рассчитать»» отображается ниже таблицы, пока расчёт не выполнен
- Кнопка ➕ в карточке «Деньги» прибавляет введённую сумму к `cashBalance` с округлением вниз до сотых
- `cashBalance` сохраняется в localStorage и участвует в экспорте/импорте JSON-файлов
- При импорте файла `cashBalance` восстанавливается из сохранённых данных
