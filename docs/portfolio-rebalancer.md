# Ребалансировка портфеля (PortfolioRebalancer)

## Общее описание

Одно-файловое React-приложение для управления портфелем активов Мосбиржи с автоматическим расчётом ребалансировки. Пользователь добавляет активы, загружает текущие цены через ISS API и видит, сколько нужно докупить/продать каждого актива для приведения портфеля к целевым пропорциям.

**Идентификация активов:** поле «Актив» принимает **тикер** (например `SBER`) или **ISIN** (например `RU000A0JX0J2`). Это позволяет добавлять облигации и другие инструменты, у которых нет короткого тикера. При вводе ISIN цена резолвится через поисковый эндпоинт ISS API (`securities.json?q=`).

**Навигация:** в шапке приложения есть меню с тремя пунктами — «Портфель», «Настройки» и «Тарифы». Пункт «Портфель» показывает основную страницу ребалансировки, пункт «Настройки» — страницу пользовательских настроек, пункт «Тарифы» — страницу тарифов (пока заглушку).

**Тарифы:** приложение показывает разный контент в зависимости от тарифа пользователя. Тарифов три: **Бесплатный**, **Базовый**, **Про**. Сейчас тариф выбирается вручную в настройках, в дальнейшем будет браться из БД.
- **Бесплатный** — максимальное количество активов в портфеле ограничено 2.
- **Базовый** — текущая реализованная функциональность (до 100 активов).
- **Про** — текущая функциональность + **группировка активов** (см. ниже).
<br>При переключении тарифа существующие активы не удаляются — ограничение действует только на кнопку «Добавить актив».

**Обновление цен и тарифы:** кнопка «Обновить цены» загружает котировки. Источник цен зависит от тарифа: на **Про** — API Т-Банка (T-Invest) через локальный backend-прокси (`server/index.js`, см. `docs/tbank-proxy.md`) — котировки без задержки; на **Бесплатном** и **Базовом** — ISS-API Мосбиржи (данные с задержкой ~15 минут). Cooldown 60 секунд применяется **только на тарифе «Про»**: после обновления следующее нажатие доступно через 60 секунд (на кнопке посекундно отображается обратный отсчёт «Обновить цены (N с)», пока идёт отсчёт кнопка неактивна и окрашена в серый цвет). На тарифах «Бесплатный» и «Базовый» кнопку можно нажимать в любой момент.

**Группировка активов (тариф Про):** настройка «Использовать группы (Про)» доступна только на тарифе Про. При включении пользователь создаёт группы активов (например, «Акции», «Облигации», «Драгметаллы») и задаёт долю каждой группы в портфеле (сумма долей = 100%). Каждый актив обязан быть привязан к группе. В этом режиме:
- **Цель %** актива считается как доля **внутри группы** (сумма целей активов группы = 100%).
- **Текущий %** актива также считается внутри группы.
- **Требуемое количество** рассчитывается от эффективной стоимости группы (`effectiveTotalValue × доля группы / 100`).
- **Распределение целей** (кнопка ⚖️ и авто-распределение) выполняется независимо в рамках каждой группы.
- Валидация портфеля проверяет: каждый актив имеет группу, сумма долей групп = 100%, сумма целей активов в каждой группе = 100%.
- При выключении групп `groupId` у всех активов сбрасывается.
- При переходе на тариф ниже Про группы автоматически выключаются.
- Группы сохраняются в localStorage и участвуют в экспорте/импорте JSON-файлов.

**Визуальное выделение групп:** при создании группы пользователь выбирает цвет через **color picker** (`<input type="color">`). Выбранный цвет сохраняется в поле `color` группы (hex-строка, например `#3b82f6`) и участвует в экспорте/импорте. Цвет группы применяется:
- К фону строк активов, принадлежащих группе (hex-цвет с 10% прозрачностью через inline-стиль `backgroundColor: hex + '1A'`).
- К цветной точке и выпадающему списку в колонке «Группа» (inline-стиль `backgroundColor`).
- К бейджу названия группы, точке и прогресс-бару в компоненте `GroupAllocations`.
- К цветной точке в списке групп на странице настроек.
Если у группы нет цвета (старые данные) — используется серый `#94a3b8`.

**Доли групп в портфеле:** при включённых группах над таблицей активов отображается компонент `GroupAllocations`, показывающий для каждой группы:
- Цветную точку и бейдж с названием группы (в цвете, выбранном пользователем).
- Прогресс-бар текущей доли группы в портфеле (в цвете группы).
- Текущий % и целевой % (заданный пользователем). Целевое значение отображается цветом `#557ce3`.
- Отклонение текущей доли от целевой с **смысловой цветовой индикацией**:
  - Группа **отстаёт** от целевой доли (`currentPercent < targetPercent`) — нужно докупить → текущий % на фоне `#FEF2F2` с текстом `#BA1C1D`, отклонение со знаком `+` (только плюс, без минуса) и цветом `#298049` (например `+0.11%`).
  - Группа **опережает** (`currentPercent > targetPercent`) — нужно продать → текущий % на фоне `#F0FDF4` с текстом `#298049`, отклонение со знаком `−` и цветом `#BA1C1D` (например `−2.50%`).
  - Группа **в балансе** (`|diff| < 1%`) — текущий % на фоне `#FEF2F2` с текстом `#BA1C1D`, отклонение без знака и цветом `#298049`.
Это позволяет мгновенно понять, какие группы требуют докупки (зелёный «+»), а какие — продажи (красный «−»).

**Цветовые индикаторы колонок таблицы активов:**
- **Купить/Продать:** положительное отклонение (нужно докупить) — **зелёный** со знаком `+`, отрицательное (нужно продать) — **красный** со знаком `−`. Это соответствует требованиям ребалансировки.
- **Текущий %:** актив **отстаёт** от целевой доли (нужно докупить) — фон `#FEF2F2`, текст `#BA1C1D`. Актив **опережает** (нужно продать) — фон `#F0FDF4`, текст `#298049`. Если актив **в балансе** (текущий % = целевой %) — фон `#dbeafe`, текст `#557ce3`.

- **Цена за шт./лот:** колонка показывает цену за 1 штуку актива (редактируемое поле) и через «/» цену за 1 лот — `цена за шт. × размер лота` (округление **строго вверх** до точности цены актива — столько же знаков после запятой, сколько у цены за 1 шт.). Поле «Лот» в таблице не отображается; размер лота (`lotSize`) определяется автоматически из ISS API (поле `LOTSIZE`) и используется в расчётах.

**Кнопка «Применить ко всем»:** в шапке таблицы, в колонке «Купить/Продать», находится кнопка **«Применить ко всем»**. Она обновляет количество **всех** активов сразу до требуемого (`requiredQuantity`), аналогично кнопке ⬇ в каждой строке, но для всего портфеля. Кнопка активна только после выполнения расчёта (когда есть `analysis`). После применения расчёт сбрасывается, и требуется новый расчёт.

**Неактивные настройки:** настройки, недоступные в текущем тарифе или нереализованные (заглушки), визуально приглушены классом `setting-disabled` (opacity 0.55, серый заголовок). Это касается:
- Выключателя «Использовать группы» при тарифе ниже Про.
- Полей «Процент брокера за покупку/продажу активов» (заглушки).

**Ключевая особенность:** расчёт выполняется **только после нажатия кнопки «Рассчитать»**, что даёт пользователю полный контроль над моментом пересчёта.

**Система учёта денежных средств:** в карточке «Деньги» отображается остаток свободных средств (`cashBalance`). По умолчанию (при нулевом остатке) поле пустое. Пользователь может ввести добавляемую сумму и нажать ➕ «Добавить», после чего она прибавится к остатку. При нажатии «Рассчитать» доступный бюджет (cashBalance + additionalCash + выручка от продажи активов) используется для докупки отстающих активов, и нетто-эффект (покупки − продажи) списывается с остатка.

**Авто-распределение целей:** целевые проценты автоматически заполняются в следующих ситуациях:
- При добавлении нового актива
- При любом изменении поля актива (тикер, количество, цена, цель)
- При удалении актива

Логика: если есть активы с `targetPercent = 0`, нераспределённый остаток делится между ними поровну. Если все цели равны 0 — 100% делится поровну между всеми активами.

**Ручное распределение:** кнопка ⚖️ «Поровну» в колонке «Цель %» позволяет вручную распределить проценты между ненулевыми активами по тому же алгоритму. Актив считается нулевым, если его поле «Цель» **пустое** (пустая строка, фокус ещё не потерян), равно **null** (blur очистил поле перед нажатием кнопки) или равно **0** — во всех случаях он получит распределённую долю.

- `analysis = useMemo(() => ...)` — массив с расчётными полями. **Зависит от `isCalculated` и `calculatedAnalysis`**. Возвращает `[]`, если расчёт не произведён. После нажатия «Рассчитать» использует сохранённый результат (с учётом бюджета), чтобы данные не менялись при перерендерах.
- `portfolioValidation = useMemo(() => ...)` — результат валидации суммы целевых процентов.

## Управление расчётом

### Принцип работы

1. Пользователь вводит данные (редактирует активы).
2. Все изменения **сбрасывают** `isCalculated` в `false` через `resetCalculation()`.
3. Пока `isCalculated === false`, таблица **не показывает** результаты анализа (колонки «Текущий %», «Требуется», «Купить/Продать» пусты).
4. После нажатия кнопки «Рассчитать»:
   - Фиксируется `calculatedTotalValue = PortfolioCalculator.calculateTotalValue(assets) + cashBalance + additionalCash` (эффективная стоимость)
   - Бюджет: `cashBalance + additionalCash + выручка от продажи активов` (деньги, полученные от продажи перевешенных активов, добавляются к доступным средствам и используются для докупки отстающих)
   - Вызывается `PortfolioCalculator.analyzePortfolio(assets, effectiveTotalValue, budget)` — докупка ограничена бюджетом с учётом выручки от продаж
   - **Кеш НЕ меняется**: `additionalCash` (если введён) прибавляется к `cashBalance` (эквивалент кнопки ➕), но списания за покупки и зачисления выручки от продаж **откладываются** до нажатия «Применить ко всем» или ⬇ (одиночное применение). Вместо обновления кеша сохраняются `calculatedSpent` и `calculatedSales`.
   - `isCalculated` устанавливается в `true`
   - `calculatedAnalysis` сохраняется — дальнейшие ререндеры не пересчитывают анализ
   - Запускаются анимации: появление строк, подсветка карточек

5. После нажатия «Применить ко всем»:
   - Количества всех активов обновляются до `requiredQuantity`
   - Кеш обновляется на сумму `adjustmentValue` по всем ещё не применённым корректировкам (исключает двойной счёт при смешанном использовании ⬇ и «Применить ко всем»)
   - Расчёт сбрасывается

6. После нажатия ⬇ в строке одного актива:
   - Количество актива обновляется до `requiredQuantity`
   - Кеш корректируется на `adjustmentValue` этой позиции (положительное = списание за покупку, отрицательное = зачисление выручки от продажи)
   - Расчёт сбрасывается для этого актива

### Сброс флага

`isCalculated` сбрасывается в `false` при:
- Обновлении цен через кнопку «Обновить цены»
- (Поле ввода стоимости портфеля и дополнительной суммы убраны)

**Расчёт НЕ сбрасывается** при:
- Изменении полей актива (тикер, количество, цена, целевой процент) — результаты остаются видимыми, пользователь сам решает, когда пересчитать
- Добавлении нового актива
- Удалении актива

## Система учёта денежных средств

### Ключевой принцип

Кеш (`cashBalance`) меняется **только при реальных операциях** (депозит через ➕, исполнение сделок через «Применить» или ⬇). При «Рассчитать» кеш не трогается — вычисляется только анализ (таблица корректировок). Это исключает двойной учёт ещё не выполненных продаж и гарантирует, что портфель всегда показывает фактическое состояние: `Стоимость портфеля = Стоимость активов + Деньги`.

### Карточка «Деньги» (PortfolioSummary)

В карточке отображается текущий остаток `cashBalance`. Пользователь может:
1. Ввести сумму в поле ввода
2. Нажать ➕ «Добавить» — сумма прибавится к `cashBalance` (с округлением вниз до сотых), поле очистится

### Карточка «Стоимость портфеля» (PortfolioSummary)

Карточка показывает **фактическую** стоимость портфеля: `totalValue + cashBalance`, где `totalValue = PortfolioCalculator.calculateTotalValue(analysis)` — та же рыночная стоимость активов, что и в карточке «Стоимость активов». Поскольку формула одна и та же, сумма никогда не расходится ни на копейку.

- До «Рассчитать»: текущая стоимость активов (текущие количества × цена) + текущий кеш
- После «Рассчитать»: та же формула — кеш не изменился (только `additionalCash` прибавился), активы не изменились. **Кеш изменится только после «Применить».**
- После «Применить ко всем»: стоимость активов (уже обновлённые количества × цена) + обновлённый кеш — итоговая сумма = исходный бюджет (100000.00)

### Логика при расчёте

При нажатии «Рассчитать»:
- Доступный бюджет = `cashBalance + additionalCash + выручка от продаж`
- `PortfolioCalculator.analyzePortfolio()` вычисляет корректировки, но **НЕ обновляет кеш**
- Возвращаемые `cashSpent` и `salesTotal` сохраняются в `calculatedSpent`/`calculatedSales` и используются позже при «Применить»
- `additionalCash`, если введён, автоматически прибавляется к `cashBalance` (то же, что и кнопка ➕)

### Логика при применении

При нажатии «Применить ко всем»:
- Количества обновляются до `requiredQuantity`
- Кеш корректируется на сумму `adjustmentValue` активных корректировок (только те, у которых `appliedAdjustmentIds` ещё не сброшен)

При нажатии ⬇ (одиночное применение):
- Количество обновляется до `requiredQuantity`
- Кеш корректируется на `adjustmentValue` конкретного актива

### Сохранение

`cashBalance` сохраняется в localStorage вместе с портфелем и импортируется/экспортируется в JSON-файлах.

## Авто-распределение целевых процентов

### Логика `distributeTargets`

Метод `PortfolioCalculator.distributeTargets(assets, emptyTargetIds = new Set())` автоматически заполняет целевые проценты. Второй параметр `emptyTargetIds` — набор id активов, у которых поле «Цель» пустое (пустая строка, фокус ещё не потерян). Актив считается нулевым, если его `targetPercent === 0` **ИЛИ** `targetPercent == null` (blur очистил поле перед нажатием кнопки ⚖️) **ИЛИ** его id находится в `emptyTargetIds`.

1. **Все цели равны 0** — 100% делится поровну между всеми активами (последнему — остаток для точной суммы 100%):
   - 2 актива → 50.0 / 50.0
   - 3 актива → 33.3 / 33.3 / 33.4
   - 4 актива → 25.0 / 25.0 / 25.0 / 25.0

2. **Есть и нулевые, и ненулевые** — оставшаяся доля `(100 - сумма_ненулевых)` делится поровну между нулевыми:
   - SBER: 50%, GAZP: 0%, TATN: 0% → SBER: 50%, GAZP: 25%, TATN: 25%

3. **Все цели ненулевые** — ничего не меняется.

> **Примечание:** параметр `emptyTargetIds` используется только при ручном распределении через кнопку ⚖️. Авто-распределение (при добавлении/изменении/удалении актива) вызывается без этого параметра.

### Механизм отслеживания пустого поля

При стирании содержимого поля «Цель» `NumericInput` вызывает колбэк `onEmptyChange(true)`, и id актива добавляется в набор `emptyTargetIds`. При нажатии кнопки ⚖️ браузер сначала отправляет `blur` полю ввода (очищая `targetPercent` до `null`), а затем `click` кнопке. Чтобы кнопка корректно видела пустое поле:

- `handleBlur` при пустом поле **не вызывает** `onEmptyChange(false)` — id остаётся в наборе пустых полей.
- `distributeTargets` считает `targetPercent == null` нулевым — даже если id выпал из набора.
- При заполнении поля извне (после распределения или ручного ввода) `useEffect` синхронизации сообщает `onEmptyChange(false)`, и id удаляется из набора.

### Триггеры вызова

`distributeTargets` вызывается автоматически при:
- **Добавлении актива** (`handleAddAsset`) — новый актив добавляется с `targetPercent: 0`, затем вызывается распределение
- **Изменении любого поля актива** (`handleUpdateAsset`) — после обновления данных вызывается распределение, что заполняет оставшиеся нулевые цели
- **Удалении актива** (`handleRemoveAsset`) — после удаления вызывается распределение для оставшихся активов

## Классы бизнес-логики

### `PortfolioCalculator`

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `floorMoney` | `value` | `number` | Округление денег строго вниз до сотых |
| `floorQuantity` | `value` | `number` | Округление количества строго вниз до целого |
| `getLotSize` | `asset` | `number` | Размер лота актива (целое, >= 1; по умолчанию 1) |
| `floorToLot` | `value, lotSize` | `number` | Округление количества (в штуках) вниз до целого числа лотов |
| `calculateTotalValue` | `assets` | `number` | Сумма `quantity × lotSize × price` по всем активам |
| `calculatePercentages` | `assets` | `number[]` | Процент каждого актива от общей стоимости |
| `calculateRequiredQuantity` | `asset, targetPercent, totalValue` | `number` | Сколько **ЛОТОВ** актива нужно для целевого процента (округление вниз до целого лота) |
| `calculateAdjustment` | `currentQuantity, requiredQuantity` | `number` | Разница между текущим и требуемым количеством (в лотах) |
| `distributeGroupTargets` | `groupAssets, emptyTargetIds` | `Object[]` | Распределение целевых процентов внутри одной группы |
| `distributeTargets` | `assets, emptyTargetIds?, groups?` | `Object[]` | Распределение целевых процентов поровну. В режиме групп — независимо в рамках каждой группы |
| `analyzePortfolio` | `assets, effectiveTotalValue, availableBudget?, groups?` | `{analysis, cashSpent, salesTotal}` | Полный анализ портфеля с ограничением бюджета. `cashSpent` — покупки (округляются вниз до копеек), `salesTotal` — выручка от продаж (округляется вниз до копеек). В режиме групп эффективная стоимость распределяется по группам пропорционально их долям |

**Модель актива и лотность:** актив описывается полями `ticker`, `quantity`, `lotSize`, `price`, `targetPercent`, `groupId`. Здесь:
- `quantity` — количество **ЛОТОВ** (целое, >= 0);
- `lotSize` — сколько **штук** актива в одном лоте (целое, >= 1, по умолчанию 1);
- `price` — цена за одну **штуку**;
- стоимость актива = `quantity × lotSize × price`.

Активы торгуются лотами (минимум 1 лот), поэтому все расчётные объёмы («Требуется», «Купить/Продать») выражаются в **лотах** и кратны лоту (округление строго вниз). Лотность определяется автоматически из ISS API (поле `LOTSIZE`) при загрузке цены и сохраняется в данных актива (`lotSize`). Поле «Лот» в таблице не отображается и не редактируется: колонка «Цена за шт./лот» показывает цену за 1 штуку и (через «/») цену за 1 лот (`цена за шт. × размер лота`, которая округляется строго вверх до точности цены за 1 штуку). Для обратной совместимости у старых сохранённых/импортированных активов без `lotSize` он нормализуется к 1.

### `MoexPriceService`
Сервис получения цен через ISS API Мосбиржи (акции, ETF, облигации, foreign shares, депозитарные расписки).

### `AssetValidator`
Валидация отдельного актива и портфеля в целом (сумма процентов должна быть 100% ± 0.5%).

## Примечания

- Минимальное количество активов — 2 (кнопка удаления блокируется для id <= 2)
- Максимальное количество активов — 100
- Цены загружаются автоматически при монтировании (если есть активы с тикерами)
- При `calculatedTotalValue = 0` требуемое количество для всех активов = 0
- После любых изменений данных кнопка «Рассчитать» переключается в синий цвет, сигнализируя о необходимости перерасчёта
- Подсказка «Нажмите «Рассчитать»» отображается ниже таблицы, пока расчёт не выполнен
- Кнопка ➕ в карточке «Деньги» прибавляет введённую сумму к `cashBalance` с округлением вниз до сотых
- `cashBalance` сохраняется в localStorage и участвует в экспорте/импорте JSON-файлов
- При импорте файла `cashBalance` восстанавливается из сохранённых данных
