# Интеграция с ISS API Московской биржи

## 📡 Используемый API

Для получения реальных цен используется **ISS API** Московской биржи:
- **URL**: `https://iss.moex.com/iss/`
- **Документация**: https://iss.moex.com/iss/reference/
- **Поддержка CORS**: ✅ Да, не требует прокси
- **Авторизация**: ❌ Не требуется

## 🔧 Реализация: `MoexPriceService`

Класс `MoexPriceService` находится в `index.html` и заменяет старую симуляцию `PriceService`.

### Как работает

1. **Запрос к API**: `GET https://iss.moex.com/iss/engines/{engine}/markets/{market}/securities/{TICKER}.json?iss.meta=off`
2. **Перебор рынков**: Актив ищется последовательно на рынках: акции → ETF → облигации → иностранные акции → депозитарные расписки.
3. **Парсинг ответа**: Извлекаются секции `marketdata` (текущие торги) и `securities` (справочные данные) для данного актива.
4. **Автоопределение доски**: Перебираются доски в порядке приоритета, пока не найдётся цена.
5. **Fallback-цепочка цен**: Если `LAST` (последняя сделка) недоступен, последовательно проверяются:
   - `MARKETPRICE` — рыночная цена (доступна даже в нерабочие дни)
   - `LCLOSEPRICE` — цена закрытия предыдущей сессии
   - `PREVPRICE` из секции `securities` — предыдущая цена закрытия

### Приоритет досок

| Доска | Режим торгов | Примеры активов |
|-------|-------------|-----------------|
| `TQBR` | Основной режим акций | SBER, GAZP, LKOH, EQMX, GOLD |
| `TQTF` | ETF / ПИФы | FXRL, FXUS |
| `TQOB` | Облигации | ОФЗ, корпоративные облигации |
| `TQTD` | Депозитарные расписки | |
| `TQPI` | Паи | |
| `SMAL` | Малые предприятия (SME) | |
| `CETS` | Валюта | USD000UTSTOM |

Если ни одна из приоритетных досок не найдена, берётся первая строка с ценой > 0.

### Fallback-цепочка цен

Когда `LAST` (цена последней сделки) недоступен (например, в выходные или нерабочее время), используется следующий порядок полей:

| Приоритет | Поле | Источник | Описание |
|-----------|------|----------|----------|
| 1 | `LAST` | marketdata | Цена последней сделки |
| 2 | `MARKETPRICE` | marketdata | Рыночная цена (доступна всегда) |
| 3 | `LCLOSEPRICE` | marketdata | Цена закрытия предыдущей сессии |
| 4 | `PREVPRICE` | securities | Предыдущая цена закрытия |

Это особенно важно для **БПИФов** (EQMX, GOLD и аналогичных), которые числятся на рынке `shares` (акции), а не `etf`, и могут не иметь сделок в текущий момент.

### Поиск по ISIN

Поле «Актив» в таблице принимает **тикер** (например `SBER`) или **ISIN** (например `RU000A0JX0J2`). Это позволяет добавлять облигации и другие инструменты, у которых нет короткого тикера.

Реализация:
1. **`isIsin(value)`** — определяет, является ли строка ISIN (12 символов: 2 буквы страны + 9 букв/цифр + 1 контрольная цифра).
2. **`resolveIsin(isin)`** — запрашивает поисковый эндпоинт `https://iss.moex.com/iss/securities.json?q={ISIN}` и извлекает `secid` (тикер) первой найденной строки.
3. **`fetchPrice(value)`** — если входная строка похожа на ISIN, сначала резолвит её в тикер через `resolveIsin`, затем получает цену по тикеру как обычно.

```javascript
/**
 * Определить, является ли строка ISIN
 * @param {string} value - Входная строка
 * @returns {boolean} true, если строка похожа на ISIN
 */
MoexPriceService.isIsin(value)

/**
 * Резолвить ISIN в тикер (secid) через поисковый эндпоинт ISS API
 * @param {string} isin - ISIN инструмента (например 'RU000A0JX0J2')
 * @returns {Promise<string>} Тикер (secid) инструмента
 * @throws {Error} Если ISIN не найден на Мосбирже
 */
MoexPriceService.resolveIsin(isin)
```

### API

```javascript
/**
 * Получить цену и размер лота актива (по тикеру или ISIN)
 * @param {string} value - Тикер (например 'SBER') или ISIN (например 'RU000A0JX0J2')
 * @returns {Promise<{price: number, lotSize: number|null}>}
 *   price - цена за одну штуку актива
 *   lotSize - размер лота в штуках (>= 1) либо null, если определить не удалось
 * @throws {Error} Если актив не найден или нет данных
 */
MoexPriceService.fetchPrice(value)

/**
 * Получить цены и размеры лотов нескольких активов
 * @param {string[]} tickers - Массив тикеров
 * @returns {Promise<{prices: (number|null)[], lotSizes: (number|null)[], errors: string[]}>}
 *   prices - массив цен (null если актив не загрузился)
 *   lotSizes - массив размеров лотов (null если определить не удалось)
 *   errors - массив сообщений об ошибках
 */
MoexPriceService.fetchPrices(tickers)

/**
 * Извлечение размера лота (LOTSIZE) из блока securities ответа ISS API
 * @param {Object} data - Распарсенный JSON-ответ ISS API
 * @param {string} boardId - Код доски (BOARDID)
 * @returns {number|null} Размер лота (>= 1) или null
 */
MoexPriceService.extractLotSize(data, boardId)
```

**Лотность:** поле `LOTSIZE` (количество штук в одном лоте) приходит в блоке `securities` ответа ISS API. Оно извлекается автоматически при загрузке цены и подставляется в поле «Лот» актива, которое пользователь может отредактировать вручную.

### Обработка ошибок

- **HTTP 404** — актив не найден на текущем рынке (проверяется следующий рынок)
- **Таймаут** — 5 секунд на запрос (через `AbortSignal.timeout`)
- **Нет данных** — актив есть, но ни одно ценовое поле не заполнено
- **Частичные ошибки** — если один актив не загрузился, остальные всё равно обновляются

## 🔄 Использование в приложении

### Автоматическая загрузка при открытии

При монтировании компонента `PortfolioRebalancer` вызывается `useEffect`, который автоматически загружает цены для всех активов с тикерами.

### Ручное обновление

Кнопка **"Обновить цены"** вызывает `handleRefreshPrices`, который:
1. Собирает все непустые тикеры
2. Запрашивает цены через `MoexPriceService.fetchPrices()`
3. Обновляет цены в состоянии (если актив не загрузился — остаётся старая цена)
4. Показывает ошибки для незагрузившихся активов

### Начальное состояние

Активы создаются с `price: 0`. После первой загрузки цен через API они заполняются реальными значениями.

## 📝 Примечания

1. **Таймаут**: 5 секунд на каждый запрос. Если API не отвечает, показывается ошибка.
2. **Выходные и нерабочее время**: В нерабочее время Мосбиржи API возвращает данные последней торговой сессии. Для получения цены используется fallback-цепочка (MARKETPRICE → LCLOSEPRICE → PREVPRICE).
3. **Rate Limiting**: ISS API не имеет строгих ограничений, но не рекомендуется делать более 10 запросов в секунду.
4. **CORS**: ISS API официально поддерживает CORS, запросы из браузера работают без прокси.
5. **БПИФы**: Биржевые паевые инвестиционные фонды (EQMX, GOLD и др.) числятся на рынке `shares` (акции), а не `etf`. Поиск по рынку `shares` стоит первым в списке приоритета, поэтому они находятся корректно.
